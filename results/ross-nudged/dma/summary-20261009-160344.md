**Timing at 8.000 ns**
- WNS -0.456 ns, TNS -4.546 ns, 10 failing endpoints; WHS +0.080 ns, so hold is met.
- The failing path is register-to-register inside `dma_data_mover` (write-side burst sizing, 12 logic levels). It is a logic-depth limit, not a constraint artifact.
- The same script fails at 8.500 ns (WNS -0.306) and closes at 9.000 ns (WNS +0.024), so about 111 MHz is the demonstrated Fmax.
- Closing 125 MHz needs a pipeline stage in `dma_data_mover` or a faster speed grade. I did not make that RTL change.

**Utilization:** 1333 LUT (989 logic, 344 distributed RAM), 831 FF, 0 BRAM, 0 DSP. BRAM is 0 because the FIFO's asynchronous read maps to LUT-RAM.

**Lint:** 12 messages, all warnings (10 ASSIGN-10, 2 ASSIGN-6), 0 errors, 0 critical. None is a real defect: they are the unselected Avalon/AHB inputs, unused AXI ID/response bits, and reserved descriptor bits.

**RTL changes:** none in `rtl/`. One testbench line in `sim/tb_pcie_dma.sv` changed, because xsim rejects `void'($urandom(seed))` at elaboration; it is now a function-call assignment.

**Things you should know**
- **I/O constraints differ from the SDC.** The 1 ns port budget is expressed as `set_max_delay -datapath_only` rather than `set_input_delay`/`set_output_delay`. The literal form produced 204 false port hold violations in the out-of-context run. Boundary hold is therefore not checked here.
- **Synthesis and implementation use high-effort settings** (PerformanceOptimized, retiming, Explore-class directives). `-retiming` is flagged as deprecated but is what the reports were built with.
- **Vivado crashed once**, in a post-route `phys_opt_design`. I removed that step and regenerated all reports, but the crash killed the first MCP session, so the final builds and the final xsim run come from a second session.
- **Lint report path:** `synth_design -lint -file` breaks silently when the path contains a space, as this checkout's does. `build.tcl` works around it and guards against the resulting black-box RAM.
